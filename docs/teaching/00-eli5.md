# The whole project, in plain English

No prior knowledge assumed. If a term anywhere in this repo is unfamiliar, it is in the [glossary](glossary.md).

## What a digital image actually is

A screen picture is a grid of tiny colored dots called pixels. Each dot stores four numbers between 0 and 255: how much red, how much green, how much blue, and how see-through it is (that last one is called alpha). That is all an image file ultimately contains: numbers. A 512 by 512 image is 262,144 dots, and at four numbers per dot that is about a megabyte of raw numbers before any cleverness.

## What compression is

Most images are predictable. Sky sits next to sky, a wall is the same color for thousands of dots in a row, and a sunset fades smoothly instead of jumping around. Compression is the art of not writing down what the reader could have guessed: instead of storing every dot, you store a rule ("same as the last dot, 40 times") or a correction ("like the dot above it, but slightly redder"). The more predictable the image, the shorter the description. "Lossless" means the reader can rebuild every original number exactly; "lossy" (like JPEG) means the reader gets something close enough to fool the eye, with the difference thrown away forever.

## Why nothing can compress everything

Imagine trying to give every book in a huge library a shorter nickname. There are fewer short nicknames than books, so if some books get shorter names, others must get longer ones. Files work the same way; this is called the pigeonhole principle, and it is why a file of pure static (noise) cannot shrink: there is no pattern to exploit, nothing the reader could have guessed. Any format that claims to shrink everything is lying somewhere. PRISM's benchmark table keeps a noise row on purpose, to show the format telling the truth.

## The two kinds of image

Here is the fork the whole project sits on. A photograph is a set of measurements: a camera sampled the light at millions of points, and detail the camera did not capture simply does not exist in the file. A logo is different: it is really a drawing recipe ("a circle here, this big, this color"), and a recipe can be redrawn at any size, razor sharp, because the math answers at every zoom level. Measurement-images are called raster; recipe-images are called vector. Blowing up a raster image cannot create real detail (the information was never captured), while a vector image scales forever. Most famous formats pick one side: PNG and JPEG are raster, SVG is vector.

## What PRISM does about it

PRISM is one file format with two compartments. The raster compartment stores every pixel exactly (lossless), compressed by predicting each dot from its neighbors and storing only the surprises. It also does something unusual: the format itself fixes the exact math a viewer must use when enlarging the image, so a PRISM file looks identical at 4x zoom in every program, which is true of no mainstream raster format. The vector compartment stores drawing recipes in a compact binary form that comes out smaller than SVG, the reigning vector format. Either compartment can be wrapped in standard encryption, and every piece of the file carries a checksum so corruption is caught instead of silently shown.

## How it was built

Rulebook first, code second. Every part of the format has a written specification (in docs/) that was agreed before the code existed, and the code is the spec's obedient implementation, checked by tests that convert images in and out and demand perfect matches. The implementation language is Rust, and the numbered lessons in this folder use each piece of the codebase to teach the language ideas it runs on.
